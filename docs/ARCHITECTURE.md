# 架构与关键决策

## 模块划分

| 模块 | 职责 |
| --- | --- |
| `gui.py` | 两份 ZIP 的文件选择、校验结果、确认、进度、取消、报告查看和另存；Tk 主线程只操作 UI |
| `archives.py` | ZIP 完整性、大小和路径校验；保存原始清单，将输入映射为受控工作文件名 |
| `analyzer.py` | 文件头格式解析；Gerber/钻孔分类与用途识别 |
| `validation.py` | 创建工作快照、唯一配对、错误/警告汇总、执行前哈希复核 |
| `models.py` | 输入、配对、校验和执行结果的数据结构 |
| `commands.py` | 参数化的 LMC 预设模板与可审查命令计划 |
| `parsers.py` | 整数答案、LIMITS 和 C-shell 导入报告的严格解析 |
| `rcom.py` | 逐命令子进程调用、超时/取消、按端口跨进程互斥、原始日志 |
| `service.py` | 全部比较、全部清理、逐层截图、异常与现场会话整理 |
| `report.py` | 内嵌图片的独立 HTML、JSON 和报告 ZIP |
| `settings.py` | 用户级配置与参数范围校验 |
| `discovery.py` | 有限范围内发现安装、配对同版本工具、读取安装器环境数据 |
| `session.py` | 复用 RCOM 会话、启动 get.exe、等待就绪和保留已启动进程 |
| `ui_components.py` | 浅色主题、卡片和图标等本地 Tk 组件 |
| `cli.py` | 无界面校验/计划/比较入口，复用相同业务代码 |

## 为什么采用这些边界

桌面界面不负责识别文件或拼装命令。业务代码可以在没有图形环境和 Valor 的测试机上验证；将来接入服务平台时，复用 `prepare_comparison` / `run_comparison` 即可。Tkinter 足以覆盖文件选择、表格、确认、后台任务及另存需求，因此初版选择标准库方案，减少现场部署依赖；需要更复杂的图形编辑和嵌入式大图浏览时可以替换界面层。

校验阶段建立工作快照，而不是到执行阶段再读取用户原 ZIP。用户确认的是已校验的具体文件；执行前复核快照 SHA-256，避免确认和执行之间的输入漂移。更换任一输入或输出目录会使界面旧校验失效。

配对优先使用明确的层用途，未知用途只接受相同文件名。自动模糊猜测可减少人工操作，但对 Gerber 比较存在错误配对的风险；本实现把歧义作为错误展示，要求用户整理输入后重新校验。

参考平台面向网表检查的识别器只需要线路、钻孔和 IPC，不能直接用于“所有 Gerber 图形比较”。此处保留其 Xpedition 命名规则，扩展阻焊、外形、钻孔图、其他光绘数据，同时不继承网表检查对 IPC、线路层连续性的前置要求。

命令计划包含全部预设阶段，但 LIMITS 和窗口 ID 依赖运行结果，不能在运行前伪造。`command_plan.json` 明确标记动态输入；`commands.txt` 和 `rcom.jsonl` 保存真正发送给 Valor 的命令和返回证据。模板以结构化参数生成一个命令字符串，再作为单个 argv 传入 `rcom`，避免 Shell 路径转义问题。

本机 Valor 编辑器使用共享可变状态，因此同一端口串行执行，不并发导入、比较或截图。每次创建新 Job，使用 `open_entity` 返回的组号定位本次编辑器。清理网格前取消所有受影响层，仅设置 Result；删除发生在这一层。不会自动清空其他 Job 或关闭整个 Valor。

成功判定同时要求完整导入、可解析的比较计数和有效截图。导入报告严格核对每个目标层及 `ok` 状态；空字符串、错误文本和多个整数都不会被当成零差异。失败后的已知网格数保留，但截图未完成的层单独标记，整体不判为一致。

RCOM 客户端取消/超时不能视作服务端事务回滚。遇到这种不确定状态时，停止后续命令，保留 Job 名称和日志供人工检查；不在可能仍运行的服务端继续发送关闭或清理命令。

安装路径发现和会话启动分开处理。发现过程只读本机安装信息，并保留有效的用户路径；启动过程在端口互斥范围内先测试连接，只有端口没有可用会话时才启动工具。GUI 启动连接和后续比较共享同一个 `ValorSession`，避免等待超时后重复启动尚在初始化的 get 进程。

`VALOR_ENV_FILE` 来自安装器，文件中的 `VALOR_DIR` 通常指向共享的 `vNPI_DIR`，并不等于版本执行目录。实现读取该文件的变量并展开引用，保留安装器设置；不会把可执行文件的父目录冒充共享数据库/系统目录。自动启动不修改系统环境或注册表。

界面继续使用标准库 Tk，增加可缩放的卡片组件和统一浅色主题。主窗口把路径配置、参数、完整日志放在次级位置，突出资料、校验和结果；后台发现和启动事件与比较事件分别进入主线程队列，等待 Valor 时可以先选择资料。

## 当前适用条件

目标环境是本机 Windows + Valor NPI 2604 的 RCOM 专用会话。附带命令接口参考资料不能替代真实机器联调。不同 Valor 版本、许可证、数据库、用户颜色及屏幕缩放可能影响导入或截图，验收时应核对实际 `rcom.jsonl`。

图形比较保持原始坐标和方向，适合校验同一坐标基准的两版加工数据。对于“仅比较形状、忽略整体平移/旋转”的需求，应另外设计显式的对齐步骤和对齐审查，不应默认应用在本次结果中。

当前支持完整 RS-274X 文件头以及可明确解析的 Excellon 格式。无法确定的隐式小数格式应优先从 EDA 重新导出；后续如增加手动导入格式设置，应将该设置和用户确认一起写入校验快照与报告。
