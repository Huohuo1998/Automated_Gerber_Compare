# UI 评审与 0.3 改进说明

当前界面已经建立了资料输入、校验摘要、图层工作区、执行操作四个清晰分区。下一步优先级是提高操作可发现性、来源辨识和结果追溯，并保持主窗口与弹窗的一致性。

| 优先级 | 观察 | 对使用的影响 | 本次处理 |
| --- | --- | --- | --- |
| 高 | “选择 ZIP”接近普通文字链接 | 首次使用不易发现核心输入入口 | 两处统一使用浅蓝填充按钮，明确按钮边界 |
| 高 | 资料卡片只显示文件名 | 不同目录下同名 ZIP 容易混淆 | 两处显示来源文件夹，长路径中部省略，悬停看全路径、点击复制 |
| 高 | 关注事项只有总数 | 用户需要切换页面再猜测对应图层 | 配对表增加校验提醒列，按层语义键或文件身份关联；悬停和详情窗显示完整说明 |
| 高 | 应用提示使用系统消息框，设置窗口另有样式 | 字体、留白、图标和按钮层级不一致 | 统一应用内确认、信息、警告、错误、图层详情与设置窗口的设计规则和图标 |
| 中 | 四个摘要卡片均采用三行排布 | 摘要占用过多垂直空间，压缩图层表格 | 辅助说明移至数值行右侧，保留统一对齐和间距 |
| 中 | 选齐两份资料还需手动校验 | 固定步骤需要重复点击 | 自动校验，使用短暂延迟合并输入变更；手动校验会取消待执行的自动校验 |
| 中 | 辅助文字偏淡、表格文字偏小 | 较大屏幕和长时间复核时阅读负担偏高 | 提高辅助文字对比度，增大表格及表头字号 |
| 中 | 主窗口、标题栏和 EXE 缺少统一标识 | 工具辨识度较低 | 原样嵌入附件 ICO，并使用其中的原生 PNG 帧显示应用内标识 |

## 交互与一致性原则

- 自动校验完成后，仍需用户确认才执行比较。自动校验只整理资料和检查配对。
- 提醒数量统计的是校验事项数。表格显示关联到当前图层的提醒；压缩包级别的提醒继续在“校验详情”中呈现，点击摘要的错误/关注事项可直接进入该页。
- 表内提醒使用简短原因和差异参数，例如“坐标精度：A 2.6 / B 2.4”。完整长说明采用悬停提示和可复制的详情窗口，避免挤占相邻的比较状态。
- “存在差异”使用关注色，“执行失败”使用错误色，分别表达正常比较结论和执行异常。
- 应用窗口和各类弹窗共用字体、颜色、图标与按钮样式；对话框居中定位，底部操作固定可见，长消息可滚动和复制。
- 文件选择与导出沿用系统文件选择器，保留系统导航、网络位置和用户熟悉的文件操作方式。

## 后续可考虑

1. **按差异或提醒筛选。** 当图层较多时，能缩短定位时间；应同步展示筛选后的数量，避免误以为其余层未参与比较。
2. **阶段条反映当前执行阶段。** 让校验、执行和报告三个阶段与真实运行状态同步，强化已有进度信息。
3. **高 DPI 与键盘操作验收。** 在目标机器的 125%/150% 缩放下检查长文件名、弹窗、Tab 顺序与默认焦点。常规窗口与小窗口已纳入自动化截图检查，实际显示设置仍需现场确认。

## 等待参数说明

RCOM 的 `communicate` 普通等待间隔由 0.1 秒改为 5 秒。该间隔到期会在内部循环捕获 `TimeoutExpired` 并继续等待，不代表命令失败。较短的连接探测和最后一次等待会按剩余总时长缩短间隔，以保留原有总超时上限。执行中的取消请求最长可能等待约 5 秒才被处理。
